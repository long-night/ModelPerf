## 二、各框架详细分析

### 2.1 Lumos (MLSys 2025)

#### 基本信息
- **论文标题**: Lumos: Efficient Performance Modeling and Estimation for Large-scale LLM Training
- **作者**: Mingyu Liang, Hiwot Tadese Kassa, Wenyin Fu, Brian Coutinho, Louis Feng, Christina Delimitrou
- **发表会议**: MLSys 2025 (第8届机器学习系统会议)
- **ArXiv**: https://arxiv.org/abs/2504.09307
- **PDF**: https://arxiv.org/pdf/2504.09307
- **单位**: Cornell University (1), Meta (2), MIT (3)
- **GitHub**: 目前未找到官方开源仓库

#### 核心思想

Lumos 是一个**基于 Trace 的性能建模与估计工具包**，专门针对大规模 LLM 训练场景设计。其核心创新在于：

1. **无需侵入式插桩**：仅利用 PyTorch Kineto 等 ML 框架内置的 profiling 工具，不需要对模型或框架进行任何自定义插桩，大幅降低使用门槛。
2. **细粒度执行图**：从 profiling traces 中构建全面的任务级执行图，精确识别所有任务间的依赖关系（包括跨 CUDA stream 的复杂依赖）。
3. **图操作与配置探索**：支持修改现有执行图来生成新配置的图，从而预测不同并行策略和模型架构下的性能。

#### 技术架构

```
Trace Collection (PyTorch Kineto)
    ↓
Trace Extraction → 提取元信息
    ↓
Execution Graph Construction → 构建任务依赖图
    ↓
Graph Manipulation → 修改并行策略/模型架构
    ↓
Simulator → 回放或预测性能
```

执行图包含两种任务类型：
- **CPU tasks**: PyTorch operators, CUDA runtime events
- **GPU tasks**: GPU kernels

依赖关系包括四种：
- Intra-thread dependency（线程内顺序）
- Inter-thread dependency（跨线程同步）
- CUDA launch dependency（CPU→GPU 发射）
- CUDA synchronization dependency（stream 间同步）

#### 关键技术特性

| 特性 | 说明 |
|------|------|
| Profiling 方式 | PyTorch Kineto（仅需 ~10 行 hook 代码）|
| 仿真算法 | 基于依赖图的离散事件仿真 |
| 支持的并行策略 | TP, PP, DP 及组合 |
| 模型架构探索 | 支持调整层数、hidden size 等 |
| 实现语言 | Python (~5,200 LoC) |

#### 评估结果

- **平台**: 生产级 ML 集群，最多 512 NVIDIA H100 GPUs (32 servers)
- **模型**: GPT-3 变体（15B 到 175B）
- **平均回放误差**: 仅 **3.3%**
- **可精确重现**: 执行时间分解、SM 利用率等细粒度统计
- **预测新配置**: 调整并行策略和模型架构时保持高精度

#### 优势与局限

**优势：**
- 使用门槛极低，不需要修改模型代码
- 能够精确捕捉现代 LLM 中复杂的计算-通信重叠行为
- 支持 What-if 分析，可用于配置优化探索

**局限：**
- 目前尚未开源
- 需要真实硬件做 profiling（单次迭代即可）
- 目前不估计系统级指标如 FLOPS 利用率、内存带宽、能耗等
- 预测新配置时假设不会出现 OOM 等意外问题

### 2.2 SimAI (NSDI 2025)

#### 基本信息
- **论文标题**: SimAI: Unifying Architecture Design and Performance Tuning for Large-Scale Large Language Model Training with Scalability and Precision
- **作者**: Xizheng Wang, Qingxu Li, Yichi Xu, Gang Lu, Dan Li, Li Chen, Heyang Zhou, Linkang Zheng, Sen Zhang, Yikai Zhu, Yang Liu, Pengcheng Zhang, Kun Qian, Kunling He, Jiaqi Gao, Ennan Zhai, Dennis Cai, Binzhang Fu
- **发表会议**: NSDI 2025 (第22届 USENIX 网络系统设计与实现研讨会)
- **论文链接**: https://www.usenix.org/conference/nsdi25/presentation/wang-xizheng-simai
- **PDF**: https://www.usenix.org/system/files/nsdi25-wang-xizheng-simai.pdf
- **单位**: 阿里云 (1), 清华大学 (2), 中关村实验室 (3)
- **GitHub**: https://github.com/aliyun/SimAI
- **开源协议**: Apache-2.0
- **Star 数**: 962+

#### 核心思想

SimAI 是**业界首个全栈高精度 AI 大规模训练仿真器**，其核心思想是：

1. **全栈集成**：选择性高保真地集成训练框架、kernel 计算和集合通信库到仿真过程中。
2. **Hijack 框架**：通过劫持主流训练框架（Megatron-LM、DeepSpeed）来生成真实的工作负载。
3. **三种运行模式**：分析模式、仿真模式、物理模式，提供不同速度与精度的权衡。

#### 技术架构

SimAI 由四个核心组件构成：

```
SimAI
├── AICB (AI Communication Benchmark)
│   └── 工作负载生成与测试套件执行
├── SimCCL (Sim Collective Communication Library)
│   └── 将集合通信拆解为点对点操作
├── astra-sim-alibabacloud
│   └── 扩展的 AstraSim 仿真引擎（集成 NCCL 算法）
└── ns-3-alibabacloud
    └── 网络仿真后端（支持包级建模）
```

#### 三种运行模式

| 模式 | 说明 | 速度 | 精度 |
|------|------|------|------|
| **Analytical** | 基于总线带宽抽象的数学建模 | 最快 | 较低 |
| **Simulation** | 基于网络拓扑建模的详细事件驱动仿真 | 中等 | 高 |
| **Physical** | 在真实 RDMA 集群上生成实际流量 | 最慢 | 最高 |

#### 关键技术特性

- **多线程加速**：通过 UNISON 将网络仿真分布到多个 CPU 核
- **Lock-free 全局上下文共享**：避免线程同步延迟
- **NS-3 基础**：实现 23× 加速，支持 1000+ GPU 集群仿真
- **支持场景**：框架参数、通信算法、NCCL 环境变量、传输协议、拥塞控制、自适应路由、网络拓扑修改等

#### 评估结果

- **平台**: 最多 1024 节点 A100 GPU 集群
- **平均对齐度**: **98.1%** 与真实结果对齐
- **适用规模**: 从小规模实验室到大规模工业环境
- **验证场景**: 各种测试场景下的新主机设计和参数设置

#### 最新版本功能 (SimAI 1.6, 2026/04)

- GPU 显存建模（推理仿真）
- Prefill-Decode 分离的显存规划
- 多请求推理工作负载的端到端仿真
- 支持 DeepSeek、Qwen3MoE、Qwen3Next 等现代模型
- 支持 Prefill/Decode 推理分离

#### 优势与局限

**优势：**
- 完全开源，社区活跃（962+ Stars）
- 业界唯一覆盖框架+通信+网络全栈的仿真器
- 三种模式灵活切换，适应不同需求
- 已在阿里云生产环境中验证

**局限：**
- 架构相对复杂，学习曲线较陡
- 需要编译安装多个子模块
- 网络仿真部分计算开销较大

### 2.3 SimuMax

#### 基本信息
- **全称**: SimuMax: a static analytical model for LLM distributed training
- **开发方**: 摩尔线程 (MooreThreads)
- **GitHub**: https://github.com/MooreThreads/SimuMax
- **开源协议**: 未明确标注（但完全开源）
- **Star 数**: 131+
- **编程语言**: Python (96.4%), Shell (3.6%)
- **论文**: 目前未发表学术论文

#### 核心思想

SimuMax 是一个**基于静态解析模型的分布式训练仿真器**，其设计灵感来自 Calculon，针对大规模 LLM 工作负载。核心思想是：

1. **双模型结合**：结合 cost model（性能模型）和 memory model（内存模型），配合 roofline model 进行仿真。
2. **参考真实实现**：参考 Megatron-LM 和 DeepSpeed 的实际实现细节。
3. **最大化计算效率**：帮助用户探索最大化计算效率的方法。

#### 技术架构

```
模型配置 + 系统配置
    ↓
Cost Model (计算量、通信量估算)
    ↓
Memory Model (显存占用估算)
    ↓
Roofline Model (性能上限分析)
    ↓
性能与显存仿真输出
```

#### 支持的特性

| 特性 | 支持状态 |
|------|---------|
| Data Parallel (DP) | ✅ |
| Tensor Parallel (TP) | ✅ |
| 1F1B Pipeline Parallel (PP) | ✅ |
| Sequence Parallel (SP) | ✅ |
| Expert Parallel (EP) | ✅ |
| ZeRO1 | ✅ |
| MoE (均衡负载) | ✅ |
| Full Recompute | ✅ |
| Selective Recompute | ✅ |
| MLA (Multi-head Latent Attention) | ✅ |
| Megatron 兼容 | ✅ |
| 策略搜索 | ✅ |

#### 仿真精度

- **显存估计**: Dense/MoE 模型误差 < **1%**
- **性能估计**: 多个主流 GPU 上最优性能误差 < **4%**
- **效率评估**: 支持不同张量形状和内存布局的计算效率评估

#### 使用场景

1. 寻找最优训练策略以最大化效率
2. 为框架/大模型算法工程师提供优化方向和调试分析
3. 为芯片厂商提供性能预测参考，辅助规格设计

#### 优势与局限

**优势：**
- 完全开源，使用简单（纯 Python）
- 显存估计精度极高（<1%）
- 内置策略搜索功能
- Megatron 兼容，模型迁移方便
- 不依赖真实硬件 profiling

**局限：**
- 尚未发表学术论文
- 主要面向自研 GPU（摩尔线程 MUSA 架构），对 NVIDIA GPU 支持通过效率文件间接支持
- 目前不支持 context parallel、通算并行、offload 等高级特性（TODO 中）
- 静态模型难以精确捕捉动态调度行为

### 2.4 DistSim (ACM Computing Frontiers 2023)

#### 基本信息
- **论文标题**: DistSim: A performance model of large-scale hybrid distributed DNN training
- **作者**: Guandong Lu, Runzhe Chen, Yakai Wang, Yangjie Zhou, Rui Zhang, Zheng Hu, Yanming Miao, Zhifang Cai, Li Li, Jingwen Leng, Minyi Guo
- **发表会议**: 20th ACM International Conference on Computing Frontiers (CF'23), Bologna, Italy
- **ArXiv**: https://arxiv.org/abs/2306.08423
- **PDF**: https://arxiv.org/pdf/2306.08423
- **DOI**: https://doi.org/10.1145/3587135.3592200
- **单位**: 上海交通大学、华为技术有限公司
- **GitHub**: 未找到官方开源仓库

#### 核心思想

DistSim 是一个**基于事件的性能模型**，专注于混合并行分布式训练。其核心洞察：

1. **Profiling 冗余消除**：在混合并行中，大量计算和通信操作在不同设备/微批次间是重复的，不需要全量 profiling。
2. **分层依赖建模**：不同并行策略有不同层次的依赖关系（DP 同步权重、MP 聚合输出、PP 传递激活值），各策略可独立建模后组合。

#### 技术架构

```
模型 + 并行策略配置
    ↓
Event Generator → 从子模型提取计算/通信事件
    ↓
Profiling → 仅需 2 个节点对所有事件进行 profiling
    ↓
Hierarchical Modeling:
    ├── Model Parallelism Modeling
    ├── Pipeline Parallelism Modeling
    └── Data Parallelism Modeling
    ↓
Timeline Combination → 完整训练时间线
```

**Event 抽象**：
- **计算事件 (Computation Event)**: 由算子名称、参数、输入形状区分
- **通信事件 (Communication Event)**: 补充 intra-node/inter-node 属性
- **Composed-event**: 组合事件，用于分层建模

#### 关键技术特性

| 特性 | 说明 |
|------|------|
| Profiling 需求 | 仅需 2 个节点（1 个不够用于测量通信）|
| 支持的并行策略 | DP, MP, PP 及其任意组合 |
| 输出 | 完整执行时间线（含每个设备的计算和通信活动）|
| 可复用性 | 事件时间可被存储和复用 |
| 替代方案 | 可用 GPU simulator（如 MGPUSim）或 operator predictor（如 Habitat）替代 profiling |

#### 评估结果

- **模型**: Bert-Large, GPT-2-345M, T5
- **批次时间预测误差**: < **3.51%**（各种混合策略）
- **设备活动预测误差**: < **5%**
- **大规模验证**: 145B GPT 模型在 128 GPUs 上（8M16P1D），与 Megatron-LM 报告数据对齐
- **策略搜索用例**: 在 48 层 Bert-exLarge 上找到吞吐量提升 **7.37×** 的混合策略

#### 优势与局限

**优势：**
- Profiling 成本极低（仅需 2 个节点）
- 可处理任意 DP/MP/PP 组合
- 事件可复用，策略搜索效率高
- 提供详细的每设备执行时间线

**局限：**
- 未开源
- 基于较早的 DNN 架构设计（Bert/GPT-2），对现代 LLM 的特定优化（如 flash attention、通算并行）支持可能有限
- 需要一定简化假设（同构设备、无网络层次）

   - 学习分层依赖建模方法
   - 了解 profiling 冗余消除技术

3. **深入阶段**：研究 **Lumos** 的论文
   - 学习 trace-driven simulation 的完整流程
   - 理解复杂依赖图（特别是 CUDA stream 间依赖）
   - 了解图操作技术用于配置探索

4. **专家阶段**：深入 **SimAI** 源码
   - 研究全栈仿真的工程实现
   - 学习 hijack 框架的技术
   - 理解网络级仿真与事件驱动仿真的结合

## 五、关键技术趋势

### 5.1 技术演进方向

1. **从静态分析到动态仿真**：早期工具（Calculon → SimuMax）主要依赖静态分析，新工具（Lumos、SimAI）转向基于 trace 的动态仿真，精度大幅提升。

2. **从单一层面到全栈覆盖**：从仅关注计算（早期）→ 计算+通信（DistSim）→ 框架+通信+网络（SimAI）。

3. **从训练到训练+推理**：SimAI 1.5+ 已支持推理仿真，反映了业界对推理性能优化的日益重视。

4. **Profiling 成本持续降低**：从需要大规模集群（早期方法）→ 仅需 2 节点（DistSim）→ 单次迭代 trace（Lumos）→ 无需 profiling（SimuMax）。

### 5.2 值得关注的新方向

| 方向 | 说明 |
|------|------|
| **多模态模型仿真** | 当前工具主要聚焦 LLM，多模态训练仿真是下一个前沿 |
| **异构集群仿真** | 支持不同 GPU 类型的混合集群仿真 |
| **故障注入与容错** | 在仿真中模拟硬件故障和网络抖动 |
| **能效建模** | 不仅估计时间，还估计功耗和碳排放 |
| **自动策略优化** | 与 AutoML 结合，自动搜索最优并行策略 |

---

## 六、总结

四个框架各有特色，代表了当前大模型训练性能仿真的不同技术路线：

- **Lumos** 在 trace-driven 仿真上做到了极致精度，适合需要精确理解训练行为的场景。
- **SimAI** 是目前最完整的工业级全栈方案，适合大规模生产环境优化。
- **SimuMax** 以极简的静态模型实现了极高的显存估计精度，适合快速策略搜索。
- **DistSim** 以创新的 event-based 方法最小化了 profiling 成本，适合资源受限环境下的策略评估。

对于入门学习，建议从 **SimuMax** 的代码和 **DistSim** 的论文入手，逐步深入理解更复杂的仿真技术。
