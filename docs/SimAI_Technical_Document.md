# SimAI 技术文档

## 1. 概述

**SimAI** 是一个面向大规模大语言模型（LLM）训练的统一高精度模拟器，旨在整合 AI 基础设施的容量规划（Capacity Planning）与性能调优（Performance Tuning）于单一框架内。由阿里云、清华大学、中关村实验室等机构联合研发，并在 **NSDI 2025** 上发表。

SimAI 通过选择性地将训练框架（Megatron、DeepSpeed）、内核计算和集合通信库（NCCL）高保真地集成到模拟过程中，实现了高精度与高效率的统一。其核心特性包括：

- **高精度**：平均偏差仅 **1.9%**（即与真实世界结果对齐度达 **98.1%**）
- **大规模可扩展性**：支持从实验室小规模环境到工业级大规模部署（1,000+ GPU）
- **全栈覆盖**：支持训练框架、计算模拟、通信模拟的完整链路
- **开源**：https://github.com/aliyun/SimAI

## 2. 背景与动机

### 2.1 AI 训练基础设施现状

大语言模型的训练需要数千甚至数万 GPU 协同工作。以 GPT-3（175B 参数）为例，需要 1,024 块高端 GPU 连续运行 34 天。为优化 GPU 利用率，主流训练框架（Megatron、DeepSpeed）提供三种并行策略：

| 并行策略 | 英文缩写 | 作用 |
|---------|---------|------|
| 数据并行 | DP (Data Parallelism) | 将数据分配到多个 GPU |
| 流水线并行 | PP (Pipeline Parallelism) | 将模型分层分配到不同 GPU |
| 张量并行 | TP (Tensor Parallelism) | 将单层计算切分到多个 GPU |

这些并行策略依赖于集合通信库（CCL，如 NCCL）管理数据交换。

### 2.2 当前模拟方案的局限性

现有模拟器通常只针对特定粒度设计，导致以下问题：

1. **多模拟器割裂**：容量规划使用流/作业级模拟（忽略包级行为），性能调优使用包级模拟（过于细节），两者不一致导致成本-性能分析失准
2. **精度与效率不可兼得**：细节模拟器性能差，粗粒度模拟器精度低
3. **开发测试复杂**：碎片化的方法增加了开发和测试难度，导致模拟与真实性能偏差大

### 2.3 四大设计目标

| 目标 | 描述 |
|------|------|
| Goal 1 | 灵活且精确的工作负载生成器，支持不同模型、参数和规模 |
| Goal 2 | 高保真集合通信模拟，包含 NCCL 的关键优化 |
| Goal 3 | 高保真计算模拟，兼具精度与可扩展性 |
| Goal 4 | 整体可扩展，能够高效运行大规模 LLM 模拟 |

## 3. 系统架构

### 3.1 整体架构

SimAI 由三大核心组件构成：

```
┌─────────────────────────────────────────────────────────┐
│                    Input Description                       │
│  (Model, Params, Framework Params, CCL Params, Topo)   │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│               Workload Generator (SimAI-WG) §3.2        │
│              "劫持"训练框架，生成精确工作负载              │
└───────────────────────────┬─────────────────────────────┘
                            │ 工作负载描述文件
                            ▼
┌─────────────────────────────────────────────────────────┐
│                  Execution Engine                        │
│  ┌─────────────┐    ┌─────────────┐  ┌──────────────┐  │
│  │ SimAI-CP    │    │ SimAI-CM    │  │ Speedup      │  │
│  │ 计算模拟器   │◄──►│ 通信模拟器   │  │ §3.5 多线程   │  │
│  │ §3.3        │    │ §3.4        │  │ 无锁全局共享   │  │
│  └─────────────┘    └─────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 工作负载生成器（SimAI-WG）

#### 3.2.1 生成工作负载文件

SimAI-WG 采用 **"劫持"（Hijacking）** 现有训练框架的方法，在单机环境下生成与真实任务完全一致的工作负载。

**核心思路**：
1. **欺骗框架**：让 Megatron/DeepSpeed 误以为运行在目标 GPU 规模的集群上
2. **设置拓扑**：将主机间拓扑配置为通用的集群配置
3. **跳过真实通信**：跳过 NCCL 中所有真实的数据传输

这样，训练框架会生成完整的计算和通信操作序列（包括算法子模块和集合/点对点通信），但不会有实际的数据传输开销。

#### 3.2.2 依赖关系定义

由于计算和通信在执行时会重叠，工作负载文件必须包含精确的依赖信息。依赖关系基于并行化框架确定，使用 Nvidia Nsight Systems 在 1,024 GPU 集群上验证。

**示例依赖关系**（TP+DP+PP 场景）：
- 实线箭头：严格的 "happened-before" 关系
- 虚线箭头：可重叠的操作
- 例如：MLP backward 子模块在 Attention backward 和 AllReduce 完成后才开始

#### 3.2.3 基准测试套件（Benchmark Suite）

基于生产环境统计，选取了覆盖小、中、大三种规模的模型：

| 模型 | 参数量 | 隐藏层 | 层数 | 序列长度 | FFN 大小 | 框架 | TP | PP |
|------|--------|--------|------|----------|----------|------|----|----|
| GPT-3 6.7B | 6.7B | 4096 | 32 | 2048 | 16384 | Megatron | 1 | 1 |
| GPT-3 13B | 13B | 5120 | 40 | 2048 | 20480 | Megatron | 2 | 1 |
| GPT-3 175B | 175B | 12288 | 96 | 2048 | 49152 | Megatron | 8 | 8 |
| LLaMA 65B | 65.2B | 8192 | 80 | 4096 | 28672 | Megatron | 8 | 2 |
| Llama 3 405B | 405B | 16384 | 126 | 8192 | 53248 | Megatron | 8 | 16 |

> 生产环境统计：94%+ 的 LLM 是 GPT-3 或 LLaMA 的变体；Megatron 和 DeepSpeed 是主导框架。

### 3.3 精确计算模拟（SimAI-CP）

#### 3.3.1 精确模拟现有 GPU

在单机运行模拟框架后，SimAI-WG 输出各子模块在目标 GPU 上的执行时间。由于实际 LLM 训练中每个 GPU 只运行单一任务，只需按工作负载文件填入各子模块的执行时间即可。精度范围为 **96.9% ~ 99.5%**。

**操作数据库**：SimAI-CP 维护一个操作数据库，记录基准套件中所有子模块在不同 GPU 和配置下的执行时间。

#### 3.3.2 细粒度内核模拟

将子模块拆分为更小的内核（Kernel），按计算密度和内存访问强度分类：

| 操作类型 | 示例内核 | 特性 |
|---------|---------|------|
| 内存带宽密集型 | Embedding, LayerNorm, Attention_QKV, GeLU | 受内存带宽限制 |
| 计算密集型 | Gemm, Core_attention, MLP-linear | 受 FLOPS 限制 |

#### 3.3.3 支持未发布 GPU（SimAI-CP-Model）

对于尚未发布的 GPU，使用 Roofline 性能模型，基于已知 GPU 的数据进行推算：

- **计算密集型内核**：
  $$\text{Time}_{\text{Comp\_New}} = \frac{\text{FLOPS}_{\text{Comp\_Known}}}{\text{FLOPS}_{\text{Comp\_New}}} \times \text{Time}_{\text{Comp\_Known}}$$

- **内存带宽密集型内核**：
  $$\text{Time}_{\text{Mem\_New}} = \frac{\text{Bandwidth}_{\text{Mem\_Known}}}{\text{Bandwidth}_{\text{Mem\_New}}} \times \text{Time}_{\text{Mem\_Known}}$$

> **注意**：建议使用架构相似的 GPU 作为基线，而非跨厂商泛化。论文使用 Nvidia A100 作为基线计算其他 Nvidia GPU。

### 3.4 精确通信模拟（SimAI-CM）

#### 3.4.1 复现 NCCL 关键流程

SimAI-CM 使用修改版 NCCL —— **SimCCL**，通过拦截关键操作来生成点对点通信列表：

| 修改点 | 说明 | 代码量 |
|--------|------|--------|
| NCCL 初始化 | 拦截 `NcclCommInitAll`，创建虚拟通信器 | 364 行 |
| 拓扑发现 | 读取用户指定的拓扑文件（XML） | 52 行 |
| 主机内通信通道创建 | 在虚拟通信器间建立通道 | ~100 行（XML） |
| 主机间通信通道创建 | 绕过 AllGather，直接创建跨主机通道 | 56 行 |
| 集合通信转换 | 拦截集合通信调用，重构为底层通信 | - |

> **总计**：在原始 NCCL 代码基础上仅修改约 **572 行代码**（共 10,000+ 行），设计非侵入式。

#### 3.4.2 多线程加速与无锁优化

**问题**：早期 SimAI 模拟 128 GPU 的 GPT-3 单轮迭代需要 **24 小时**，而真实硬件仅需 2 秒。

**解决方案**：
1. **多线程实现**：基于 UNISON [3]，自动划分网络拓扑并将任务调度到不同线程
2. **无锁全局变量共享**：
   - 问题：多线程更新共享数据结构（如全局锁/原子操作）导致性能瓶颈
   - 解决：将全局变量按节点 ID 索引隔离，各线程独立访问，无需加锁
   - 效果：相比单线程版本提速 **23 倍**，相比多线程加锁版本提升 **15%**

### 3.5 关键技术总结

| 技术 | 实现方式 | 效果 |
|------|---------|------|
| 框架劫持 | 欺骗 Megatron/DeepSpeed 在单机模拟集群行为 | 生成精确工作负载 |
| 子模块-内核转换器 | 将 LLM 子模块拆分为细粒度内核 | 支持高级优化模拟 |
| SimCCL | 修改 NCCL 生成点对点通信列表 | 精确复现通信模式 |
| 多线程+无锁 | UNISON 基础 + 节点隔离的全局变量 | 23 倍提速 |

## 5. 生产环境收益

### 5.1 指导新 GPU 主机设计

#### H100 主机设计

**问题**：GTC 2023 发布的 H100 性能显著提升，如何确定网络带宽以（1）充分利用 H100 性能（2）最小化资本支出？

**SimAI 模拟结果**（1,024 H100 GPU，GPT-3 175B）：

| 网络带宽 | 性能表现 | 建议 |
|---------|---------|------|
| 100Gbps | 基准 | - |
| 200Gbps | 显著提升 | - |
| 400Gbps | 比 200Gbps 再提升 19% | 投资回报显著 |
| > 400Gbps | 不推荐 | 受 PCIe Gen5 × 16（512Gbps）上限限制 |

**最终设计**：每台主机 8× H100 + 8× 2×200Gbps CX7 NICs，SimAI-CP 精度 **> 98%**。

#### H20 主机设计

H20 计算性能低于 H100，所需网络带宽相应减少：

| 带宽升级 | 端到端性能提升 |
|---------|--------------|
| 100Gbps → 200Gbps | **11%** |
| 200Gbps → 400Gbps | **6%** |

**决策**：每台主机 8× H20 + 8× CX6 NICs（200Gbps），性价比最优。

### 5.2 量化 Scaling-up 收益

**发现**：传统的 TP 组大小 = 主机内 GPU 数量的经验法则缺乏定量分析。

**SimAI 实验结果**（图 11）：

1. **最优 TP 大小**：8 GPU 主机中，GPT-3 13B/LLaMA 65B/GPT-3 175B 的最优 TP 分别为 4、8、8
2. **更多 GPU ≠ 更好**：即使 GPU 数量增加，若 TP 大小不合适，性能可能下降
3. **权衡关系**：更大的 TP 减少每 GPU 的内存和计算负载，但增加通信开销

**生产指导原则**：
- TP 参数应能容纳整个模型层
- 增加 TP 大小会降低端到端吞吐，更好的策略是增加 DP 组数量
- 主机设计应考虑 LLM 的演进特性，按层最大尺寸确定主机内 GPU 数量

## 6. 经验与演进

### 6.1 模拟器演进历程

#### Phase 1：基于 ASTRA-sim 的原型

- 使用 ASTRA-sim 作为基础，内置 DNN 工作负载仅为粗略近似
- 与真实训练偏差高达 **92.1% ~ 143.9%**
- **结论**：不可用于精确 LLM 模拟

#### Phase 2：从零构建 SimAI-WG

- 分析 Megatron/DeepSpeed 开源代码，在模拟器中重建工作流
- **缺点**：
  1. 需要大量人力资源理解框架细节（耗时数月）
  2. 训练框架快速演进，持续更新困难
- **结论**：放弃此方法，转向 "劫持框架" 方法

#### Phase 3：劫持框架方法（当前）

- 精确复制所有子模块及其关系
- 实现高精度模拟（平均偏差 1.9%）

### 6.2 计算模拟精度提升

| 方法 | 结果 |
|------|------|
| 理论模型推导 | 精度低 |
| 细粒度 GPU 模拟器 | 精度高但延迟过大，无法集成 |
| **SimAI-CP（操作库）** | **最佳平衡**，两阶段演进：子模块 → 细粒度内核 |

### 6.3 通信模拟精度提升

| 问题 | 解决方案 |
|------|---------|
| ASTRA-sim 算法与 NCCL 不一致 | 放弃优化 ASTRA-sim，从头模拟 NCCL 关键行为 |
| 即使复现 NCCL 算法仍不准确 | 创建 SimCCL 完整模拟 NCCL 初始化、拓扑、通道创建 |

### 6.4 模拟即服务（Simulation as a Service）

**目标**：将 SimAI 转变为易于使用的模拟服务，满足各团队需求。

**实现**：
- **去 GPU 化**：解耦 SimAI 与 GPU 软件栈，识别并 Hook 所有 CUDA 相关函数，可在任何主机运行
- **任务调度**：基于 Kubernetes 的集群管理，将请求调度到负载最轻的主机
- **参数调优**：支持调整 TP、拓扑、模型参数、并行策略等
- **细粒度监控**：前端系统展示模拟过程中各指标的时序变化

## 8. 结论

SimAI 是一个面向大规模 LLM 训练的统一高精度模拟器，主要贡献包括：

1. **统一框架**：将容量规划与性能调优整合，避免多模拟器碎片化的不一致问题
2. **高精度**：
   - 通过 "劫持" 训练框架生成精确工作负载
   - 通过 SimCCL 复现 NCCL 关键行为，实现包级通信精度
   - 通过操作数据库和 Roofline 模型实现精确计算模拟
3. **高可扩展性**：多线程 + 无锁全局变量共享，实现 23 倍提速
4. **生产验证**：已在阿里云生产环境服务多团队，指导 H100/H20 主机设计，量化扩展收益
