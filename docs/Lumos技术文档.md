## 一、文档概述

Lumos 是一个面向大规模 LLM（大语言模型）分布式训练的 **trace-driven 性能建模与估计工具包**。它通过利用机器学习框架（如 PyTorch）内置的性能分析工具收集运行时 trace，构建详细的 task-level 执行图，并基于该执行图进行性能回放与 what-if 分析，从而帮助研究人员和工程师在无需大规模物理部署的情况下，准确预测不同模型配置和并行策略下的训练性能。

本文档系统梳理了 Lumos 的核心技术架构、执行图构建方法、依赖关系模型、执行图操作机制、仿真引擎原理，以及在真实生产集群上的评估结果，旨在为使用该工具或参考其设计思想的技术人员提供全面的参考。

---

## 二、背景与动机

近年来，大语言模型（如 ChatGPT、LLaMA、PaLM 等）的参数量已从数十亿快速增长至数千亿级别。训练这些模型需要分布式部署在大量 GPU 集群上，涉及复杂的 **3D 并行策略**（数据并行、张量并行、流水线并行）以及计算与通信的精细重叠优化。

然而，现有性能建模方法面临以下关键挑战：

1. **运行时 trace 解读困难** —— ML 框架生成的 trace 通常密集且晦涩，难以有效解读和诊断性能瓶颈。
2. **复杂依赖建模缺失** —— 大规模训练中计算与通信的重叠引入了复杂的流间依赖关系，现有工具往往无法准确捕获。
3. **配置搜索成本高** —— 并行策略和模型架构的配置空间极为庞大，在真实硬件上逐一实验代价高昂、周期漫长。

Lumos 的设计目标正是解决上述问题：在仅使用框架内置 profiling trace 的前提下，构建精确的执行图模型，实现对 LLM 训练行为的准确刻画，并支持低成本的新配置性能估计。

## 三、系统架构与核心设计

### 3.1 工作流概述

Lumos 的整体工作流程分为四个阶段：**Trace 收集**、**执行图构建**、**执行图操作**、**仿真与估计**。

首先，通过 PyTorch Kineto 等内置工具收集一次真实运行的 profiling trace，仅需在训练脚本中添加约 10 行代码即可捕获 CPU 算子、CUDA 运行时事件和 GPU kernel 的元数据。随后，Lumos 从原始 trace 中提取关键信息，构建包含所有任务及其依赖关系的详细执行图。用户可通过 Lumos 提供的接口修改模型配置（如层数、隐藏层大小）或并行策略（如数据并行度、流水线并行度），Lumos 会自动操作现有执行图生成新的执行图。最后，仿真引擎使用新图进行性能回放或预测，输出整体执行时间以及细粒度的执行特征。

### 3.2 执行图构建

Lumos 的执行图包含两类核心任务节点：

- **CPU 任务** —— 包括所有在 CPU 上执行的 PyTorch 算子和 CUDA 运行时事件。对每个 CPU 任务，记录其运行的具体线程 ID。
- **GPU 任务** —— 包括所有在 GPU 上执行的 kernel。对每个 GPU 任务，记录其元数据及负责的 CUDA 流 ID。

与传统 trace-based 建模方法（如 Daydream、dPRO）需要大量自定义插桩不同，Lumos 仅依赖框架原生能力，无需修改模型或框架代码，显著降低了使用门槛和 profiling 开销。

### 3.3 依赖关系模型

准确建模任务间的依赖关系是 Lumos 实现高精度性能仿真的关键。Lumos 识别并维护了四类依赖关系：

| 依赖类型 | 描述 |
|----------|------|
| **CPU-to-CPU** | 包括同一线程内的顺序执行（intra-thread）和跨线程阻塞（inter-thread）两种关系。 |
| **CPU-to-GPU** | GPU kernel 由 CPU 端的 CUDA 启动事件（如 `cudaLaunchKernel`）触发，通过 correlation ID 关联。 |
| **GPU-to-CPU** | CPU 端的同步事件（如 `cudaStreamSync`）阻塞执行，直至对应 GPU kernel 完成。 |
| **GPU-to-GPU** | 包括同流顺序执行和跨流事件同步（`cudaEventRecord` + `cudaStreamWaitEvent`）。 |

其中，**GPU 流间依赖**是 Lumos 相比现有方法的核心增强之一。大规模训练中，为减少通信开销，通常将计算 kernel 与通信 kernel 在不同 CUDA 流上并发执行。Lumos 通过解析 `cudaEventRecord` 和 `cudaStreamWaitEvent` 事件对，精确捕获流间的同步依赖关系，从而准确刻画并行执行行为。

### 3.4 执行图操作

Lumos 的核心价值之一在于支持对现有执行图进行操作，以模拟新的配置方案。当前支持两类修改：

- **并行策略调整** —— 包括数据并行度扩展（仅需调整通信任务执行时间）和流水线并行度调整（需重新划分阶段、更新流水线调度顺序并插入同步通信任务）。
- **模型架构调整** —— 包括修改 Transformer 层数（复制/删除层任务并重建依赖）和修改隐藏层大小或前馈网络大小（调整相关算子的输入张量维度并更新执行时间）。

在操作过程中，Lumos 保留原始 trace 中的依赖模式，确保新执行图在逻辑上的正确性。目前暂不支持张量并行度的修改，因其通常固定于单节点内部且通信开销极高。

### 3.5 仿真引擎

Lumos 的仿真引擎接收原始或修改后的执行图，通过维护 ready 任务队列和处理器状态，模拟任务的实际调度与执行过程。算法初始化时确定**固定依赖**（如同一线程上任务的顺序关系），运行时动态分配**运行时依赖**（如流同步需要等待的前序 kernel）。

仿真输出与真实 profiling trace 格式一致，包含每个任务的开始时间、持续时间等完整运行时信息。这使得用户不仅能估计总迭代时间，还能分析细粒度的执行特征，如 SM 利用率、计算与通信重叠比例等。

## 四、评估与实验结果

### 4.1 实验环境

评估在一个生产级 ML 集群上进行，使用多达 **512 块 NVIDIA H100 GPU**（32 台服务器），通过 8x400Gbps RoCE 网络互联。软件环境为 CUDA 12.4、PyTorch 2.5、TransformerEngine 0.12.0。实验采用 NVIDIA 开源的 GPT-3 实现，涵盖从 15B 到 175B 参数的四种模型变体，并在多种 3D 并行配置下进行测试。

| 模型名称 | 参数量 | 层数 | 隐藏层 | 前馈网络 | 注意力头 |
|----------|--------|------|--------|----------|----------|
| GPT-3 15B  | 15B  | 48 | 6144  | 12288 | 48 |
| GPT-3 44B  | 44B  | 48 | 12288 | 24576 | 48 |
| GPT-3 117B | 117B | 96 | 12288 | 24576 | 96 |
| GPT-3 175B | 175B | 96 | 12288 | 49152 | 96 |

### 4.2 执行回放准确性

在保持原有配置不变的情况下，Lumos 对真实执行进行回放仿真，以验证其建模准确性。结果表明：

- **迭代时间误差** —— Lumos 在所有配置下的回放误差基本低于 5%，平均误差仅 **3.3%**。相比之下，dPRO 的误差最高达 21.8%，平均误差 14%。
- **执行分解准确性** —— Lumos 能够准确还原暴露计算、重叠执行、暴露通信和其他（空闲）四类时间分量的比例，而 dPRO 由于无法建模流间依赖，系统性地高估重叠时间并低估总迭代时间。
- **SM 利用率还原** —— 在时间轴上以 1ms 为粒度对比 SM（流式多处理器）利用率，Lumos 的回放曲线与真实测量高度吻合，而 dPRO 出现明显波动和偏差。

### 4.3 新配置性能预测

Lumos 支持从现有 trace 出发，通过执行图操作预测新配置下的性能，包括：

- **并行策略扩展** —— 以 GPT-3 15B 的 TP=2, PP=2, DP=4 为基线，Lumos 准确预测了 DP 扩展至 8/16/32、PP 扩展至 4/8 以及同时扩展 DP 和 PP 的性能，平均预测误差仅 **4.2%**。
- **模型架构变化** —— 通过修改层数、隐藏层大小等参数生成模型变体（20B、28B、30B、44B），Lumos 的预测值与实际测量值高度一致，验证了其对架构修改的建模能力。

## 五、讨论与局限性

Lumos 的 profiling 开销极低：仅需少量代码插桩，且单次迭代捕获足以表征稳定执行模式。其执行图后处理阶段框架无关，可适配 TensorFlow 等其他框架。方法论上也不局限于 LLM，可扩展至其他基于 Transformer 架构的模型。

当前局限性包括：

1. **功能范围** —— 目前专注于执行时间的建模与仿真，尚未覆盖 FLOPS 利用率、内存占用、带宽使用、能耗效率等系统级指标。
2. **假设前提** —— 在预测新配置时，假设模型在新设置下正常运行，不考虑内存溢出等异常。
3. **张量并行** —— 暂不支持修改张量并行度，因其通常固定且通信开销极高。
4. **Kernel 运行时估计** —— 对于配置变化引入的全新 kernel（如新的通信算法），目前依赖内部分析模型估计，尚未集成通用 kernel 性能预测工具。

未来工作将聚焦于扩展系统级指标支持、集成更多通信与计算 kernel 性能模型，并将应用范围拓展至分布式推理场景。

---

## 六、总结与展望

Lumos 作为一种面向大规模 LLM 训练的 trace-driven 性能建模与估计工具包，通过详细的执行图构建和精确的依赖关系建模，实现了对复杂分布式训练行为的高保真仿真。在生产级集群上的验证表明，其执行回放平均误差仅 **3.3%**，新配置预测误差约 **4.2%**，显著优于现有方法。

Lumos 的 what-if 分析能力使得研究人员和工程师能够在无需大规模硬件资源的情况下，高效探索模型架构和并行策略的优化空间，大幅降低实验成本并加速迭代周期。随着 LLM 训练规模的持续增长和部署复杂度的不断提升，像 Lumos 这样的精确性能建模工具将成为系统优化和资源配置决策中不可或缺的基础设施。
